# Security policy

## Reporting a security or privacy concern

Report privately through
[GitHub's report form](https://github.com/JoelA510/JoelA510/security/advisories/new),
or open this repository's [Security tab](https://github.com/JoelA510/JoelA510/security)
and choose **Report a vulnerability**. Do not post sensitive details in a public
issue, discussion, or pull request.

Include the affected file, URL, or commit, how you found the problem, and its
impact. For exposed information, report its location rather than repeating the
information or attaching an unredacted copy.

The repository owner, @JoelA510, handles reports. There is no guaranteed response
or resolution deadline. The owner will reply in the private report, assess the
concern, and coordinate a correction and any public disclosure. Reporter credit
is included only with your consent.

## What's in scope

This repository publishes the GitHub profile README and its supporting assets.
It does not host the applications featured in the profile.

- Accidental exposure of private information or credentials in the README,
  assets, or repository history.
- Unauthorized or malicious changes to profile content, images, or links,
  including links redirected to phishing or malware.
- Security problems in assets maintained in this repository.

Each linked application and the portfolio site have their own repository and
reporting policy. Report problems there using that repository's Security tab or
SECURITY.md; this policy is specific to the profile repository, not an
account-wide policy. Vulnerabilities in GitHub itself belong to GitHub's
security reporting process.

Ordinary factual corrections, broken links, and presentation issues can use
GitHub issues when they contain no private information or vulnerability details.

## Handling boundaries

Do not use exposed credentials, follow through with a phishing attempt, or
collect other people's private information to prove a finding. Stop after
obtaining minimal evidence and report it privately. This policy does not
authorize testing linked applications or third-party systems.

## Supported content

Corrections are made on `main`, which supplies the current profile content.
There are no application releases or maintained older versions. Exposure in
historical commits remains relevant even after the current content is corrected.
